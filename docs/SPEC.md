# Спецификация продукта

## Цель

Автоматически строить и обновлять растровый XYZ-слой карты с персональными велотреками пользователя. Слой включается в nakarte.me (и аналогичных клиентах) по URL шаблона тайлов.

## Зафиксированные решения

| Тема | Решение |
|------|---------|
| Потребитель карты | Публичный **nakarte.me**, без self-host nakarte |
| Источник файлов | **HealthFit → Dropbox** (файлы `.fit`) |
| Триггер обновления | **Старт / `sync`:** полный `sync-once`. **Пока агент работает:** **FS watch** папки Dropbox Desktop. Webhook/туннель на ПК — не используем (см. [OPERATIONS.md](./OPERATIONS.md)) |
| Формат трека | `.fit`, без дополнительной «аналитической» обработки (пульс, мощность и т.п. не нужны) |
| Визуальный стиль | Сеть линий как **Komoot personal tracks**, не размытый Strava heatmap |
| Цвет | **Один** цвет; от частоты меняется прозрачность (опционально чуть толщина) |
| Частота | Чем чаще участок в **разных тренировках**, тем заметнее |
| Редкие дороги | Должны быть **хорошо видны** (высокий `alpha_min` при count ≥ 1) |
| Деплой v1 | Счёт на **ПК**, отдача тайлов через **GitHub Pages** |
| Перенос на VDS | Смена ingest/publish адаптеров + копирование `data/state`; ядро не переписывать (см. [DEPLOYMENT.md](./DEPLOYMENT.md)) |

## Пользовательский сценарий

1. Тренировка пишется на Apple Watch → Apple Health.
2. HealthFit в фоне кладёт `.fit` в выбранную папку Dropbox.
3. На ПК: при **включении агента** (или `sync`) — полный догон локальной папки Dropbox; если агент **уже работает** — FS watch create/delete в этой папке.
4. **Создание:** add в аккумулятор → dirty-тайлы → publish (v1 → GitHub Pages).
5. **Удаление:** remove вклада → publish обновлённых тайлов.
6. В nakarte.me custom layer с URL (v1 пример):

   `https://<user>.github.io/<repo>/tiles/activity-heatmap/{z}/{x}/{y}.png`

   После переноса на VDS меняется только этот URL.

## Нефункциональные требования

- Идемпотентность: один и тот же файл Dropbox (`id`) не должен дважды усиливать участок; повторный delete того же id — no-op.
- Инкрементальность: на create/delete пересчитываются только dirty-тайлы, не вся карта.
- Обратимость: для каждой обработанной активности хранится её вклад (visit-mask / эквивалент), чтобы delete мог сделать `counts -= 1` по тем же ячейкам без полной пересборки.
- `counts[cell]` никогда не уходит ниже 0; при `count = 0` ячейка снова полностью прозрачна.
- Публичный HTTPS и стабильный URL шаблона тайлов.
- Тайлы с альфа-каналом (прозрачный фон), без подложки — подложка из nakarte.

## Вне скоупа (v1)

- Self-host nakarte.
- Несколько цветовых шкал / фильтров по годам / типам спорта (можно заложить позже отдельными префиксами URL).
- Приватный доступ к тайлам (Cloudflare Access и т.п.) — опционально позже.
- Сложный replace содержимого файла на том же path (если Dropbox даёт новый id — как create+delete старого; иначе — rebuild или явная политика в реализации).
- Источники кроме Dropbox (Google Drive, Strava API и т.д.).

## Критерии приёмки v1

1. После появления нового `.fit` в папке Dropbox слой обновляется без ручных действий.
2. После удаления `.fit` из Dropbox вклад этой тренировки пропадает со слоя (участки только из неё исчезают; общие с другими — остаются, но реже).
3. В nakarte.me линии маршрутов читаются на подложке; одиночный выезд заметно виден.
4. Участок, проеханный многими тренировками, заметно плотнее одиночного, но остаётся **линией**, не тепловым пятном.
5. Повторная доставка того же файла и повторный delete не ломают плотность.
