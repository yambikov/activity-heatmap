# Запуск в терминале

Повседневный режим: агент смотрит папку Dropbox, при появлении/удалении `.fit` пересчитывает тайлы и пушит на GitHub Pages. Лог видно прямо в этом окне терминала.

## Один раз: окружение

```bash
cd ~/Desktop/dev/activity-heatmap
python3.12 -m venv .venv
source .venv/bin/activate
pip install -e .
```

Проверь `.env`: `WATCH_DIR`, `PUBLISH_MODE=github_pages`, `PAGES_SECRET_PATH`, `GITHUB_PAGES_REPO`, `TILE_URL_PREFIX`.

Дальше в **каждой** новой вкладке терминала:

```bash
cd ~/Desktop/dev/activity-heatmap
source .venv/bin/activate
```

## Команды

| Команда | Когда |
|---------|--------|
| `activity-heatmap agent` | **Основной режим.** Sync на старте, потом watch до Ctrl+C |
| `activity-heatmap sync` | Разовый догон (агент выключен / проверить всё) |
| `activity-heatmap publish` | Залить все локальные тайлы (первый деплой / починка) |
| `activity-heatmap rebuild` | Полная пересборка из всех FIT |
| `activity-heatmap rerender` | Только перерисовать PNG (цвет, толщина) |
| `activity-heatmap -v agent` | То же + DEBUG (события парсера, git-детали) |

Не запускай параллельно `agent` и `sync` на один `DATA_DIR` — есть lock.
Если процесс умер, а пишет «DATA_DIR занят» — удали `data/state/.lock` и запусти снова
(живой процесс с тем же pid lock сам не снимет; мёртвый — снимет автоматически).

## Как запустить агент

```bash
cd ~/Desktop/dev/activity-heatmap
source .venv/bin/activate
activity-heatmap agent
```

Окно терминала **не закрывай** — пока процесс жив, логи пишутся сюда. Остановка: `Ctrl+C`.

После старта сначала полный sync, затем строка вроде:

```text
FS watch: …/HealthFitExporter (debounce=1.5s). Ctrl+C — стоп.
```

## Что видно в логе

Лог **цветной** (в обычном терминале). Сначала план, потом шаги.

### Старт / разовый sync

```text
23:40:01 › Скан в папке: 96 .fit  …/HealthFitExporter
23:40:01 › План  новых=1  исчезло=0  уже в базе=95  ранее-skip=0
23:40:01 › + добавляю 1 файлов…
23:40:04 ›   загружен [1/1] 2024-05-01_….fit  → тайлов 380
23:40:04 › Итог  +1  −0  skip=0  dirty=380  всего_активностей=96
23:40:04 › Pages готовлю 380 файлов → ветка gh-pages
23:40:08 › ✓ push ok +380 −0 → yambikov/activity-heatmap
23:40:08 › 👁 watch слежу за …  Ctrl+C — стоп
```

| Строка | Значение |
|--------|----------|
| `Скан` | Сколько `.fit` на диске |
| `План новых=…` | Сколько реально надо добавить/удалить |
| `загружен [i/n]` | Прогресс по новым файлам + сколько тайлов пересчитано |
| `удалён [i/n]` | Прогресс по исчезнувшим |
| `Итог` | Сводка sync |
| `✓ push ok` | Ушло на GitHub Pages |
| `подождём` | Файл ещё качается из Dropbox — повторит позже |

### Пока агент работает

```text
23:41:10 › ● файл появился: 2026-10-25_ride.fit
23:41:12 › … события улеглись → sync + publish…
23:41:12 › План  новых=1  …
23:41:15 ›   загружен [1/1] …  → тайлов 210
23:41:15 › ↑ публикую 210 тайлов…
23:41:18 › ✓ готово тайлы на Pages обновлены (210)
```

Удаление: `● файл исчез` → `− удаляю` → `удалён [1/1]` → push.

`debounce=1.5s` — пауза после последнего события (Dropbox пишет файл кусками).

### Если менять нечего

```text
› План  новых=0  исчезло=0  …
› ✓ менять нечего — слой актуален
```

## Типичный день

1. Открыл терминал → `source .venv/bin/activate` → `activity-heatmap agent`.
2. Катаешься → HealthFit кладёт `.fit` в Dropbox → в логе `файл появился` → `загружен` → `push ok`.
3. В nakarte слой подтянется после обновления кэша (обычно сразу или через минуту).
4. Закончил — `Ctrl+C` или оставь агент работать.

Агент выключен несколько дней — один раз `activity-heatmap sync` или снова `agent` (догонит на старте).

## URL слоя в nakarte

Из `.env`, переменная `TILE_URL_PREFIX`, шаблон:

```text
{TILE_URL_PREFIX}/{z}/{x}/{y}.png
```

В настройках кастомного слоя выставь примерно: **minZoom 5**, **maxZoom 19**
(тайлы есть до z=17; ближе карта растянет последний зум — трек не пропадёт).

Не публикуй полный URL с секретом в открытых чатах.
